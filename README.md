# Somenow
**Someday → Today**

여행 로망을 실제 예약으로 잇는 크롬 새 탭 확장 프로그램.
새 탭을 열 때마다 여행지 사진 한 장과 항공권 버튼이 뜬다.

## 1. 목적
- 사람은 "언젠가 가야지"라고 말한다. 그 "언젠가"에 가격과 날짜를 붙여 "오늘"로 만든다.
- 수익: 항공·호텔 제휴 링크 클릭 → 예약 수수료.
- 성격: 본업과 무관한 부업. 서버 없이, 방치 가능한 구조로 시작.

## 2. 첫 버전(v0.1) 사양
새 탭 화면 구성:
1. 배경: 여행지 사진 1장 (Unsplash API, 하루 1회 교체, 오프라인 시 마지막 사진 유지)
2. 상단: 도시 이름 + 한 줄 문장 (예: "도쿄 — 골목마다 다른 저녁이 있다")
3. 하단: [항공권 보기] 버튼 1개 → 제휴 링크 (임시: 스카이스캐너 검색 URL)
4. 우측 하단: 사진 출처 표기 (Unsplash 라이선스 요건)

넣지 않는 것: 회원가입, 위시리스트, 적금 목표, 음악, 호텔 버튼, 다국어. 전부 v0.2 이후.

## 3. 파일 구조
- `manifest.json` — Manifest V3, `chrome_url_overrides.newtab`
- `newtab.html` — 화면
- `newtab.js` — 사진 요청, 도시 선택, 버튼 링크
- `style.css` — 전체 화면 배경, 글자 위치
- `data/cities.json` — 도시 60개. 이름, 도시코드, 한 줄 문장, Unsplash 검색어, 인천 출발 직항 소요분 `fly_min_icn`, 시간대 `tzid`, 여행 적기 `best`, 좌표 `lat`/`lon`(날씨용), 적기 기후 `climate`, 가볼 곳 `sights`(3), 먹을 것 `foods`(3), 실무 정보 `currency`/`language`/`visa`/`plug`/`transit`
- `icons/` — 16 / 48 / 128px

프라하, 암스테르담, 비엔나, 프랑크푸르트, 뉴욕, 뮌헨, 로스앤젤레스, 마드리드, 샌프란시스코, 밀라노,

도시마다 한 줄 문장, Unsplash 검색어, 인천 출발 직항 소요시간(`fly_min_icn`, 분), 시간대(`tzid`, 예: Asia/Tokyo), 여행 적기(`best`)를 갖는다.
시차는 저장하지 않고 `tzid` 로 그때그때 계산한다 — 브라우저 시간대와 비교하므로 출발지가 어디든, 서머타임 기간에도 맞는다.
직항이 없는 도시는 넣지 않는다(화면에 "직항 N시간"으로 표기하므로).

## 5. 일정
- 1주차: 뼈대. 내 크롬에서 사진·문장·버튼이 뜨고 버튼이 이동하면 완료.
- 2주차: 제휴 3곳 신청(트립닷컴·스카이스캐너·아고다). cities.json 30개 작성. 해상도 2종 점검. 제휴 승인 후 버튼 링크를 제휴 링크로 교체(스카이스캐너 직접 URL은 봇 검사 발생).
- 3주차: 크롬 웹스토어 등록($5). 아이콘, 스크린샷 3장(1280×800), 설명문 한/영, 개인정보 처리방침 페이지. 스토어 설명문에 '새 탭 변경 안내가 뜨면 유지를 누르세요' 문구 넣기.
- 4주차~: 네이버 여행 카페 2곳, 인스타 1건 소개. 주 1회 설치 수·클릭 수 기록.

### v0.2 기술 과제
① 오프라인 대비 사진을 URL이 아닌 바이트로 저장 — 완료(2026-08-28). 하루에 사진을 새로 받을 때 폭 1280 한 장만 데이터 URL로 `somenow_last_bytes` 에 저장(2MB 초과 시 저장 생략). 폴백 순서: 오늘 사진 → 마지막 사진 주소 → 저장된 바이트 → 단색 배경.
② 창 크기별 캐시 빗나감 대응 — 완료(2026-08-28). 사진 폭을 1280/1600/1920/2560 네 계단으로만 만든다(`WIDTH_STEPS`). 창 크기가 조금 달라져도 같은 주소라 다시 받지 않는다.

## 8. 규칙
- 실제 크롬에서 동작 확인 전 스토어 업로드 금지.
- 사진은 Unsplash·Pexels 무료 라이선스만.
- 제휴 링크 사용 사실을 스토어 설명·개인정보 처리방침에 명시.
- 제휴 계정·API 키는 이 파일에 적지 않는다(`.env`, Git 제외).

### v0.3 (2026-08-28 밤)
사용자 피드백 5건을 반영한 판.

1. **사진이 도시와 무관하게 나오던 문제** — Unsplash `photos/random` 은 검색어와 상관없는 사진이 섞였다. `search/photos` 의 관련도 상위 12장 안에서 무작위로 고르도록 바꿨다.
2. **새 탭이 뜨는 데 걸리던 시간** — ① 사진의 대표색(`color`)을 먼저 깔고 ② 저장해 둔 그림(1280px)을 기다림 없이 즉시 그린 뒤 ③ 큰 사진이 오면 위에 얹는다(`background-image` 두 장을 겹쳐 교체 순간의 깜빡임이 없다). 페이드 900ms → 520ms.
3. **출발지** — 브라우저 시간대로 추정(Asia/Seoul → 서울)하고 설정 패널에서 31개 도시 중 바꿀 수 있다. 항공권 링크의 출발 공항이 함께 바뀐다. 직항 소요시간은 인천 기준 값만 갖고 있으므로 출발지가 서울일 때만 표시한다. 출발지와 같은 도시는 목적지에서 건너뛴다.
4. **항공권 버튼** — 알약 버튼을 밑줄 있는 작은 글자 링크로. 셔플·하트도 48px → 34px 고스트 버튼.
5. **셔플이 한 박자 늦던 문제** — 원인 두 가지. ① 누른 뒤에야 그 도시 사진을 받기 시작했다 → 다음에 보여줄 도시를 미리 정해 사진까지 받아 둔다(새 탭당 1개, 오늘 캐시가 8개가 되면 중단. Unsplash 무료 키는 시간당 50회). ② 누르는 순간 화면을 비우고(is-ready 해제) 기다렸다 → 이제 새 사진이 준비될 때까지 이전 사진을 그대로 깔아 둔다. Unsplash 다운로드 핑은 미리받기 때가 아니라 실제로 화면에 쓸 때 보낸다(`pinged` 플래그).
6. **글자가 먼저 바뀌고 사진이 뒤따르던 문제** — 사진 한 장짜리 배경을 바꾸면 교체가 순간 잘라내기가 되어 툭 끊긴다. 사진 레이어를 두 장으로 만들어 새 사진을 위에 겹쳐 띄우고 서서히 나타나게 했다(이전 사진은 다 나타난 뒤 내린다). 글자도 따로 바꾸지 않고 사진이 준비된 그 순간에 함께 바꾼다. 사진이 0.8초 안에 안 오면 글자만 먼저 보여주고, 어떤 이유로든 2.5초가 지나면 무조건 글자를 띄운다.
   주의 ①: 사진 레이어에는 `pointer-events: none`, 본문 `.stage` 에는 `z-index: 10` 이 반드시 있어야 한다. 없으면 배경이 버튼 클릭을 가로챈다(실제로 겪은 버그).
   주의 ②: 아래 장을 내리는 타이머는 내리기 직전에 "그 사이 이 장이 다시 위로 올라오지 않았는지" 확인해야 한다. 새 탭에서는 저장본 → 큰 사진으로 연달아 두 번 바뀌는데, 이 확인이 없으면 첫 번째 타이머가 두 번째로 띄운 사진을 지워 "사진이 떴다가 사라지는" 증상이 난다(실제로 겪은 버그).
7. **새 탭에서 사진이 글자보다 늦던 문제(2차)** — 새 탭마다 저장본을 띄운 뒤 큰 사진을 다시 받아 덧씌우고 있었다. 같은 사진이 두 번 그려지니 "사진이 늦게 따라온다"고 보였다. ① 저장본을 그 화면에 필요한 폭(최대 1920)으로 저장하고 폭을 함께 기록한다 ② 저장본이 화면보다 크거나 같으면 큰 사진을 아예 받지 않는다 ③ 그래도 더 받아야 하면 페이드 없이 제자리에서 갈아끼운다(같은 그림이라 티가 나지 않는다). 결과: 창 크기가 그대로면 새 탭에서 네트워크 요청 0회, 사진 교체 0회.
8. **도시와 사진이 어긋나던 문제(베이징인데 취리히 사진)** — 원인 두 가지.
   ① 사진을 못 받으면 "마지막으로 성공한 사진"을 깔았는데, 그게 다른 도시 사진이었다 → 폴백은 **같은 도시 것만** 쓴다. 없으면 대표색 위 은은한 그라데이션으로 가고 작가 표기도 감춘다.
   ② 도시를 바꿀 때 글자를 먼저 바꾸고 사진을 기다렸다 → 이제 새 사진이 준비될 때까지 이전 사진과 이전 글자를 **함께** 유지한다(최대 6초, 그 뒤에는 그라데이션으로 정리). 첫 화면만 0.8초 뒤 글자를 먼저 보여준다.
   함께 넣은 것: Unsplash 응답의 `X-Ratelimit-Remaining` 을 보고 한도(무료 키는 시간당 50회)에 걸리면 30분간 API를 부르지 않는다. 미리받기도 5분에 한 번으로 제한. 저장하는 사진에 `iata` 를 함께 남겨 어느 도시 것인지 판단한다.
   참고: 웹스토어 등록 전에 Unsplash 앱을 Production 승인(시간당 5000회)으로 올려야 한다. 지금은 Demo 키(50회)다.
9. **전체 톤** — 조용한 에디토리얼. 영문 도시명을 넓은 자간의 머리글로 얹고, 도시명은 굵기 250, 문장은 300. 정보 줄은 자간을 넓혀 작게. 스크림은 위아래 띠 대신 은은한 비네트.

### v0.4 (2026-08-28)
콘텐츠와 화면 정리.

- **도시 카드**: 하단 ⓘ 버튼을 누를 때만 올라온다. 평소 화면은 그대로 비워 둔다. 내용은 현재 날씨 / 여행 적기와 기후 / 가볼 곳 3 / 먹을 것 3 / 알아두기(통화·언어·비자·전기·공항에서).
- **현재 날씨**: Open-Meteo(가입·API 키 불필요, 출처 표기 필요). 도시별 30분 캐시. WMO 날씨 코드를 한국어로 옮겨 표시.
  - 확인 필요: Open-Meteo 무료 이용은 비상업 기준이다. 제휴 링크가 있는 이 확장이 해당되는지 스토어 등록 전에 확인하고, 필요하면 유료 플랜이나 다른 무료 소스로 바꾼다.
- **위시리스트 D-day**: 목록에서 도시별 목표 날짜를 넣으면 "D-83" 으로 표시되고, 카드 머리에도 "가는 날까지 D-83" 이 뜬다.
- **비자 정보 기준일 2026-08-28**: 영국은 ETA 사전 승인 의무(2026.2.25.부터), 셰겐은 무비자 90일이며 ETIAS 는 2026년 말 시행 예정(현재는 불필요), 중국은 무비자 30일(2026년까지 연장), 베트남 45일. 수수료 금액은 자주 바뀌어 적지 않았다. **반년마다 재확인할 것.**
- **화면**: 항공권 버튼을 반투명 알약으로 되돌리고(사진 위에서 글자만 있으면 잘 안 보였다), 항공권·하트·ⓘ·셔플 줄을 설정 버튼과 같은 맨 아래 줄로 내렸다.

## 11. 부록: 제휴 신청 절차 (쉬운 순서)
왜 하나: 버튼을 눌러 예약이 되면 수수료를 받기 위해. 승인까지 1~2주 걸리므로 먼저 신청해 둔다.

### 준비 (한 번만)
1. 제휴사는 "당신의 사이트를 보여달라"고 한다. 스토어 등록 전이므로 GitHub 공개 저장소가 소개 페이지 역할을 한다.
   - github.com 가입 → 저장소 `somenow` 를 Public 으로 생성 → 코드 푸시.
   - 신청서의 사이트 URL 칸에는 이 저장소 주소를 적는다.
2. 신청서 공통 답변 (복사해서 사용):
   - 채널: Chrome new tab extension (브라우저 확장 프로그램)
   - 대상: 한국 사용자
   - 상태: 출시 전(pre-launch), 크롬 웹스토어 등록 예정
   - 홍보 방식: 새 탭 화면의 항공권 검색 버튼
3. 돈 받을 곳: 페이팔 계정 또는 은행 계좌 준비.

### 신청 3곳 (순서대로)
1. 트립닷컴 — trip.com 하단 "제휴 프로그램" → 가입 신청 → 위 공통 답변 기재. 항공권 링크의 1순위 후보.
2. 아고다 — partners.agoda.com → Sign up → 공통 답변 기재. 호텔용이므로 지금은 승인만 받아 둔다(v0.2 대비). 거절되면 스토어 등록 후 재신청.
3. 스카이스캐너 — 직접 제휴는 어려우므로 travelpayouts.com 가입(무료) → 카탈로그에서 Skyscanner 검색 → Join 신청. 네트워크 안에서 별도 심사가 있다.

### 승인 후
- 승인 메일이 오면 이 파일 10번 제휴 칸에 승인일 기재.
- 대시보드에서 딥링크(추적 ID 붙은 항공권 검색 주소) 발급 → newtab.js 의 buildFlightUrl 본문만 교체.
- 교체 후 확인 3가지: 버튼 클릭 시 추적 ID가 주소에 붙는가 / 대시보드에 클릭 1건이 잡히는가 / 두 단어 도시(Da Nang 등)가 정상인가.
- 수수료율은 블로그 글이 아니라 승인 후 대시보드의 실제 수치를 기준으로 기록한다.
